## 补译：汉化组自身的 46 处遗漏

汉化组的 `Longinus.dat` 里有 46 处**原文照抄日文**或**说话人/章节标题未译**。逐条与源载荷比对，字节完全一致（57 条含假名的串与 `Longinus.dat` 零差异）——不是本项目管道丢失，是素材本身如此。

补译以**日文原文**为准，术语与引号沿用汉化组既有约定：

| 日文 | 中文 | 依据 |
|---|---|---|
| `あかり` | 明里 | 汉化组正文已用（5467 处） |
| `メアリー` | 玛丽 | 同上（7091 处） |
| `電話の悪魔` | 电话恶魔 | 同上（1371 处，`『』` 引号） |

引号规则：普通台词 `「」`，电话恶魔的台词 `『』`。

### 有意不译（共 11 条，不是漏译）

| 类型 | 例 | 原因 |
|---|---|---|
| 语气词 / 喘声 | `「っ！？」`、`～～～～っっ！！` | 无实义的发音符号 |
| 译注引原文 | `（译注：此处用典“一皮むけば…”）` | 原文是注解的引用材料 |
| 占位符标注 | `{表情/かお}` | 排版标注，不是台词 |

这些字节在 GBK 下合法（假名区 GBK 与 EUC-JP 同码），随包字体字形齐备，实机显示为「中文里夹日文」，不乱码。

## 修改流程

```
resource/patch/retranslate.json    键 "文件名:字节偏移"，值 {ja, zh}
        ↓  mamba run -n EDA python script/retranslate.py --dry-run
        ↓  mamba run -n EDA python script/retranslate.py
resource/patch/scripts/*.ps3       就地写入
        ↓  python script/build_patch.py
patch/data/update/*.ps3
```

- 键用**字节偏移**，不用串下标：就地写入会在被编辑串尾部留下 NUL 填充，`strings()` 因此多切出空串、后续下标整体漂移；偏移恒定不变。
- `ja` 是补译前原文快照，用于校验「该偏移上确实还是那句日文」。幂等：内容已等于译文也接受。出现第三种内容 → 报错，不覆盖。
- 新串 GBK 字节数必须 ≤ 原串可用空间（引擎偏移不能动，见 `doc/engine-mechanics.md` §8）。超长报错，不截断。
- `--dry-run` 只报告不写盘。

## 为什么能保证 100% 正确

不是靠测试覆盖率，是靠结构：就地写入不改任何偏移，`code` / `unknown` / 头部逐字节不变，所以 `verify()` 的四项断言都是**必然等式**而非抽样：

1. `code` 段与原来逐字节相同；
2. `unknown` 段同上；
3. 头部 11 个 u32 逐字段相同；
4. 每条串按**原区间**核对：被编辑的 == 新内容 + NUL 填充，未编辑的 == 原内容；并用 `string_at()` 按偏移模拟引擎读取。

补译后全库复核：172510 个串引用全部有效，未被引用的 396 条**全是填充空串**（无任何偏移指向）。
