# 踩坑与返工教训

每条格式：规则（结论）+ 为什么（症状/依据）。

## 1. `DllMain` 里不能 `LoadLibrary`

代理 DLL 一进来就想 `LoadLibrary("cnpatch.dll")`，加载器锁内调用直接失败，返回值 `487`（`ERROR_INVALID_ADDRESS`），且没有任何提示。
⇒ 规则：`DllMain` 只做「同模块内能做」的事（内存补丁、`AddFontResourceExW`、IAT 钩子），需要额外模块时 `CreateThread` 起一个线程，在线程里加载。

## 2. 工具链不产 `.reloc` 时，基址必须显式给

本机 m2w64 的 `gcc -m32` + `ld -m i386pe` 产不出 `.reloc` 节，两个我们自己造的 DLL 同时映射时就抢不到首选基址，同样报 `487`。
⇒ 规则：代理用 `--image-base 0x10000000`，`cnpatch.dll` 用 `--image-base 0x6A000000`；开工前先 `objdump -h` 确认没有 `.reloc`，再决定要不要指定基址。

## 3. OTF(CFF) 永远进不了游戏的字体列表

症状：`AddFontResourceExW` 返回成功、`EnumFontFamiliesExA` 也回调到了我们的字体，但游戏设置页的字体列表里就是没有。
判据：回调里读 `fonttype` —— OTF/CFF 是 `2`(`DEVICE`)，真 TrueType 是 `4`(`TRUETYPE`)；游戏只收 `4`。
⇒ 规则：随包字体必须是 glyf 轮廓。`script/build_font.py` 用 `Cu2QuPen` + `TTGlyphPen` 转轮廓，`sfntVersion` 改成 `\0\1\0\0`，并补 `maxp`/`post`。

## 4. 字体族名不必须是中文（原结论已推翻）

曾记录「族名必须是 GBK 中文，否则 ASCII 名被双字节配对成乱码」。实测否定了这条对**玩家自带字体**的适用性：纯 ASCII 族名（`AOTEST`）与缺 `0x804` 记录的中文族名（`测试字体`）都能被 `EnumFontFamiliesExA`（charset 134、`fonttype=4`）正常枚举，实机下拉框里能找到、选中后渲染无豆腐块。

当年看到的「`AAAA` 显示成侬傲…」是真的，但那是**引擎自己绘制字体名**那条路径的现象，不影响字体注册与选择。两者是不同的路径，不要把它们并成一条规则。
⇒ 规则：随包字体为了显示美观用中文族名，但这不是硬性要求；玩家字体中英文名都可以，唯一硬要求是 TrueType(glyf) 轮廓（见 §3）。

## 5. 配置页显示的名字与实际渲染用的名字必须是同一串

症状：设置页里字体名显示正常，正文却整屏豆腐块。
原因：配置钩子返回了中文名，`CreateFontA` 里仍用另一个（ASCII）名字，GDI 找不到字族就退回西文字体，整个文本对象都缺字。
⇒ 规则：一个全局串同时喂给「配置显示」与 `CreateFontA`，不允许两份字面量。

## 6. 别接管 `cmvs.cfg` 的 `FONT=`

想把字体项固定成中文，最直觉的做法是改配置文件或接管读配置的入口。实测：引擎退出时会把内存里的字体名写回配置文件，下一轮启动我们的值就被覆盖了，表现为「第一次好、第二次变回默认」。
⇒ 规则：走 `GetPrivateProfileStringA` 钩子，只在键名是 `FONT` 时返回我们的名字，配置文件本身不动。

## 7. `data/update/start.ps3` 永远不会被读到

`start.ps3` 自己负责把 `data/update` 挂到最高优先级，所以它只能来自 `data/code/`；放进 `data/update/` 是一份死文件。
可疑现象：脚本都换成了中文，标题栏却始终是英文标题 —— 这就是同一个自举顺序问题。
⇒ 规则：交付物排除 `start.ps3`（`script/build_patch.py` 的 `SKIP`），标题改走 `SetWindowTextA` 钩子。

## 8. PB3B 的字面像素是「分块优先」序，不是光栅序

症状：编解码往返后，首个 16×16 分块（`x < 16` 那一列）正确，之后整体错位。
原因：解码端按 `for y块 { for x块 { for 块内行 } }` 逐行取 `columns` 字节，编码端若按整幅光栅序输出就对不上。
⇒ 规则：编码必须同序取像素；用「自造图 + 真实图」双往返（逐字节比较）验证，别只看尺寸。

## 9. PB3B 头部是自加密，且依赖文件尾字节

`enc[i] = (plain[i] + raw[len-47+i]) ^ raw[len-3+(i%2)]`：加密用到的样本在**文件最后 47 字节**。
⇒ 规则：先拼出完整文件（头部 + flags 区 + data 区），再用最终尾部回填头部；先加密后扩容等于把头部写错。

## 10. 标题栏里的「号」是 SJIS 全角空格

标题串形如 `Aoi Tori[ver.1.03] R18` + `81 40` + `- 章节名 -`。`81 40` 是 SJIS 全角空格，GBK 模式下解成「号」，历史截图里的 `R18号` 就是这么来的。
⇒ 规则：钩子里等长替换 `81 40 → A1 A1`（GBK 全角空格），其余字节不动。

## 11. 用户的质疑优先于我的推断

一次真实反例：日志写着字体注册成功、`font-enum ... ours=FOUND`，我据此判断「字体已进列表」，而用户看列表说没有 —— 用户是对的。
原因：我的枚举判据只证明「能枚举到」，没证明「游戏列表会收」（过滤条件、`fonttype`、charset 都不同）。
⇒ 规则：判据要选**和游戏同一条路径**的（同 charset、同 `fonttype`、同过滤条件）；近似判据只能用来排除，不能用来确认。

## 12. 汉化组素材的缺口不是 bug

`intcode.ps3` 没被汉化（汉化组的 85 份 = 除它之外全部脚本），它本身是纯 ASCII 的引擎内部标签；另外 85 份脚本里 **72618 条非 ASCII 串全部是合法 GBK**，没有 SJIS 残留。
⇒ 规则：看到「某处还是英文」先对照素材本身有没有这一项，不要为了「看起来更完整」去动纯 ASCII 的内部调试标签。

## 13. 不要用脚本模拟点击驱动游戏做验证

为拿设置页截图写过 `SetCursorPos` + `mouse_event` 脚本，坐标随窗口位置/DPI 漂移：想点「系统设定」，实际点中「开始游戏」直接进了剧情。
⇒ 规则：实机验收的截图与现象由人工提供；能离线判定的（编解码往返、槽位命中、清单一致性）才自动化。（与本机 `9nine` 项目 §16 同源，两处吃过同样的亏。）

## 14. 「默认值」不等于「存储值」：改默认，别覆盖用户选择

引擎的 `FONT` 项在 `cmvs.cfg` 里**根本不存在**：`sub_41D490` 里
`GetPrivateProfileStringA("MESSAGE_INFO","FONT", lpDefault = "ＭＳ ゴシック", ...)`，
默认字体名是写死在 exe 里的字面量，不是配置文件内容。
早先的实现加了个 `GetPrivateProfileStringA` 钩子，只要读到 `MS Gothic` 就换成我们的字体 —— 后果是
玩家在设置页选回 `MS Gothic` 也读不回来，等于把这个选项废了。
⇒ 规则：**改默认值本身**（就地改那几处默认串），不要拦截读取；键存在就原样透传。

## 15. 同一个默认串在 exe 里有好几份拷贝，权威的那份是调用点的参数

`ＭＳ ゴシック` 在 exe 里有 4 份（`.rdata` 1 份、`.data` 3 份），另有 1 份 ASCII `"MS Gothic"`。
先后改了 `.data` 那三份 + ASCII 那份，`CreateFontA` 拿到的仍是 SJIS 全角名 —— 因为真正生效的是
`sub_41D490` 里 `push offset byte_4D0BF8` 这个 **`lpDefault` 参数**。
⇒ 规则：改字符串常量前先用 xref 找到**调用点**，确认哪一份是参数/被 `lstrcpyA` 的目标，
不要按「名字一样就都改」猜；全部改掉也无妨，但必须知道哪一处是决定性的。

## 16. 抄期望字节时别信自己手写的编码

上一条那 4 份默认串，我按 `cp932('ＭＳ ゴシック')` 的印象手写成 `82 6C 82 73 81 40 ...`，
实际字节是 `82 6C 82 72 20 ...`：`Ｓ` 是 `0x8272` 不是 `0x8273`，中间是 **ASCII 空格 0x20**，
不是 SJIS 全角空格 `81 40`。结果校验全不过、补丁「命中 1/5」，排查花了三轮。
⇒ 规则：期望字节一律从文件里**读出来**再写进代码（或用脚本生成表），不要凭印象手抄十六进制。

## 17. 改完就以为生效，是测试里最贵的错

验证「用户存了 `FONT=MS Gothic` 就该用 MS Gothic」时，我往 `cmvs.cfg` **追加**了一段
`[MESSAGE_INFO] FONT=MS Gothic`，而文件里前面已经有 `[MESSAGE_INFO] FONT=思源黑体`。
Windows 的 INI 读取取**第一个**匹配，于是追加的那行被彻底忽略，日志显示「还是思源黑体」——
差点得出「引擎无视配置」的错误结论。
⇒ 规则：改配置文件做实验时**替换**原有的键，不要追加；改完先 `grep` 确认唯一性，再看日志。
